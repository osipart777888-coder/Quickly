# Повторный аудит Quickly — 21 октября 2026

Исходный коммит: `62e35540f5c4c82bd9533f9549118b0ccb2192d5`.
Проверено на macOS Apple Silicon, Python 3.12, PostgreSQL 15, Docker.
Все почтовые испытания использовали синтетические адреса и loopback SMTP/IMAP.
Рабочая база не использовалась для нагрузок, повреждения архивов и имитации аварий.

## Интерфейс

Добавлены сроки/интервалы, общий предел соединений, сводка группы, полный технический
журнал и CSV с фильтрами. Различаются принятие сервером, получение на собственном
ящике, папки, отсутствие данных, временная недоступность, истечение, отказ и
неизвестный результат. Измеряется время до обнаружения, включая интервал опроса.
CSV не содержит паролей, токенов, тела письма или служебных заголовков; формулы
табличных редакторов обезвреживаются. Нет выдуманной статистики спама/репутации
клиентских рассылок или отождествления технического ответа с ответом человека.

Квота ящика 5/сутки, интервал 1 минута, групповая квота N и одна исходная проверка
на участника; каждый участник отправляет один раз. Повтор внутри минуты и
исчерпанная квота отдельно блокируются. Предел соединений 4, чтению максимум 2.
Каждый размер выполняется новым Python-процессом. RAM/CPU включают приложение
и локальные почтовые фикстуры этого процесса; PostgreSQL работает отдельно.
SQL-счётчики охватывают измеренный worker-процесс, не внутреннюю работу PG.

Воркеры приводятся в действие непрерывно, без ожидания минутного таймера.
Это измерение их полной обработки, **не календарное время реального расписания**.
Штатный предел 20 отправок за такт сохранён: 100/250/500 требуют минимум
5/13/25 тактов, то есть около 4–5/12–13/24–25 минут без дополнительных ожиданий.
Медленный SMTP DATA не остановил другие аккаунты. Задержки, разрывы после
принятия, socket timeout, отказ авторизации, 451, API 429/503 и quota-403 проверены
отдельными регрессиями. Внешних почтовых сервисов и реальных адресов в стенде нет.

восстановления не было. Программа была временно остановлена. Сопоставление с
проверенной копией подтвердило сохранность прежних записей, после чего новая
версия запущена. Этот обходной способ больше не использовался: штатное
восстановление теперь переключает подготовленные базы и сохраняет прежнюю.
Последнее обновление затронуло только очистку ошибок/CSV, без изменения схемы;
контроль сохранности прошёл.

Обновлялся только Quickly. Docker daemon и сторонние приложения не
перезапускались. Тестовые контейнеры относятся к отдельной сети/тому. Старые
тома, исходная рабочая база и прежние резервные копии не удалялись.

## Оставшиеся ограничения

- Сохранён один SMTP-аккаунт с ошибкой соединения. Успешный пилот Gmail/Microsoft/
  Яндекс/Mail.ru не проводился. OAuth consent, реальные
  квоты/тарифы, папки, внешняя доставка и bounce/complaint-потоки требуют отдельной
  разрешённой проверки с настоящими собственными ящиками.
- Не выполнялась физическая перезагрузка Mac или глобальный restart Docker Desktop:
  это затронуло бы другие проекты. Проверяются LaunchAgent и отдельные контейнеры.
- Предел соединений относится к одному процессу; Mac запускает один сервер.
  Для нескольких процессов/хостов требуется отдельная общая координация.
- Автоматический откат требует доступных PostgreSQL и журнала; предыдущая БД и
  dump сохранены, но поломка всего диска требует внешней резервной копии.
- Quill advisory остаётся; локальная доставка не доказывает репутацию домена,
  попадание клиентских писем во «Входящие» или отклик людей.

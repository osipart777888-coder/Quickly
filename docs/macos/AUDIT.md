## Найденные проблемы и требуемые проверки

1. Интерфейс входа показывает только Google/Microsoft, хотя локальные register/login API существуют.
   Без OAuth это мешает первому запуску; требуется вернуть форму локального входа.
2. `_ensure_secrets` копирует ключ шифрования и JWT из окружения в БД. Нужно исключить это при внешних ключах.
3. При отсутствии Fernet шифрование допускает plaintext. Для этой установки ключ обязателен и находится вне Git.
4. Cookie входа всегда Secure, локальная HTTP-установка требует отдельной настройки с ограничением loopback.
5. Исходный Dockerfile не использует lockfile npm; зависимости Python имеют только нижние границы.
6. Запись EmailLog перед сетью сохраняется, но очередь удаляется после отправки. При аварии в промежутке
   требуется запрет автоматической повторной отправки с неопределённым результатом.
7. Суточные лимиты должны учитываться атомарно при параллельных слотах, включая диагностические письма.
8. Необходим общий выключатель с сохранением в PostgreSQL; реальная массовая отправка не разрешена пользователем.
9. Общая диагностика между собственными ящиками, история и расписание требуют дополнительного раздела.
10. XLSX, согласие, чёрный список и локальная классификация ответов требуют проверки/доработки.
11. OAuth notification-токены пользователя в исходной модели используют обычный Text.
12. Резервные копии с внешними ключами требуют сохранения secrets.env отдельно от dump.

## Исправления для первого запуска

- Возвращена форма локальной регистрации и входа с использованием штатного API.
- HTTP cookie допускается только при явном QUICKLY_LOCAL_HTTP=true и loopback BASE_URL.
- Внешние JWT/Fernet-ключи больше не копируются в app_setting; для Mac оба обязательны.
- Убрана запись начала DATABASE_URL (с потенциальным паролем) в журнал планировщика.
- Добавлен .dockerignore: секреты, venv, импорты и резервные копии исключены из контекста сборки.
- OAuth-токены Gmail, Microsoft и уведомлений переведены на EncryptedText (как SMTP-пароли).
- В режиме обязательных внешних ключей запись секрета без Fernet завершается ошибкой.
- SDK всех облачных AI-провайдеров вынесены в requirements-ai-optional.txt; локальная установка не требует их.
- Первичный npm audit обнаружил 20 проблем зависимостей (10 high, 9 moderate, 1 low).
  Исправления и повторная проверка будут отражены в итоговом отчёте.
- Python audit: найдены python-jose/ecdsa без исправленных версий и старый pip.
  Штатные HS256-токены переведены на совместимый PyJWT; python-jose/ecdsa исключены.
  pip обновляется до исправленной версии и на Mac, и в Docker-сборке.
- В Docker используется Debian bookworm, чтобы pg_dump/pg_restore соответствовали PostgreSQL 15.
- npm ci использует lockfile со всеми платформенными optional-зависимостями.
- SMTP unit-тесты больше не зависят от DNS для документационных mail/imap/smtp.example.com:
  локальный VPN выдаёт этим именам синтетические частные IP. Защита SMTP от SSRF в приложении не ослаблена.
- После замены JWT-библиотеки и обновления pip повторный pip-audit: известных уязвимостей нет.
- Проверка шести ошибок штатного набора на неизменённом upstream подтвердила все шесть:
  четыре теста не передают авторизацию, один ждёт запрета удаления привязанного ящика,
  ещё один проверяет подсчёт ответов. Защита API не будет отключаться ради прохождения тестов.

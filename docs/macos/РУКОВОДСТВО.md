# Quickly на вашем Mac

Для первого знакомства откройте [пошаговую инструкцию по меню и действиям](ПОШАГОВО.md).
Этот документ содержит дополнительные сведения о подключении и сохранности данных.

## Запуск и вход

Откройте `~/Applications/Quickly.app` и выберите **Открыть Quickly**.
Адрес интерфейса: **http://localhost:8765**. Доступ разрешён только с этого Mac.
Docker Desktop должен работать. После следующего входа в macOS Quickly запускается
автоматически; открывать окно браузера автоматически он не будет.

Администратор уже создан: **admin**. В Quickly.app выберите **Данные входа**:
пароль читается из macOS «Связка ключей», запись `local.quickly.admin`.
Кнопка копирования переносит пароль в буфер только по вашему нажатию.
Если пароль администратора будет изменён, обновите эту запись в «Связке ключей».
`admin@quickly.local` — локальный идентификатор администратора, не почтовый ящик.

**Остановить Quickly** останавливает только его контейнеры. Listmonk и другие
приложения не затрагиваются. Папку проекта не переносите без повторной установки
оболочки: ярлык и автозапуск используют её абсолютный путь.

## Сначала подключите собственные ящики

Пока ящиков нет, интерфейс готов к настройке, а кампании заблокированы общим
переключателем. На главной видны реальные нулевые показатели.

В разделе **Почтовые аккаунты** используйте:

- **Добавить Яндекс / Mail.ru / корпоративный ящик** — простая форма SMTP/IMAP.
  Начальный лимит — 5 попыток в сутки. Введите полный email и пароль приложения.
- **Добавить ящик** → Google / Microsoft — штатное подключение через OAuth.
- **Импорт аккаунтов из CSV** — сначала скачайте образец. Это конфигурации ваших
  отправителей; они не попадают в базу получателей. Пароли шифруются при сохранении.

После добавления нажмите **Проверить подключение**. Для SMTP проверяются авторизация
и IMAP, без отправки письма. Для Google/Microsoft проверяется доступ официальным API;
это не отдельный SMTP/IMAP-вход. Успешная проверка чтения не гарантирует, что провайдер
разрешит последующую отправку: это покажет отдельная диагностическая отправка.

| Провайдер | SMTP | IMAP | Авторизация |
|---|---|---|---|
| Яндекс | smtp.yandex.ru:465, SSL | imap.yandex.ru:993, SSL | Пароль приложения |
| Mail.ru | smtp.mail.ru:465, SSL | imap.mail.ru:993, SSL | Пароль внешнего приложения |
| Gmail | Официальный Gmail API | Официальный Gmail API | Google OAuth |
| Outlook / Microsoft | Microsoft Graph | Microsoft Graph | Microsoft OAuth |
| Корпоративный / другой | Параметры администратора, SSL или STARTTLS | SSL, обычно 993 | Разрешённый провайдером пароль приложения |

Для SMTP на порту 587 применяется STARTTLS. Для этой установки не сохраняйте IMAP
без TLS. Не отключайте проверку сертификатов.

В Яндексе разрешите доступ почтовых клиентов по IMAP и использование паролей
приложений. В Mail.ru включите доступ внешних сервисов по IMAP/SMTP и создайте
специальный пароль. Обычный пароль от учётной записи не используйте:
[Яндекс](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/mail-clients-troubleshooting),
[Mail.ru](https://help.mail.ru/mail/login/mailer/).

На этом Mac VPN выдаёт синтетические DNS-адреса. Для четырёх серверов Яндекса/Mail.ru
подготовлен точный список доверенных имён. Для корпоративного сервера раскройте
пункт **VPN: разрешить точное имя…**, добавьте именно его SMTP/IMAP-имя и повторите
проверку. Частные сети, localhost и служебные адреса остаются заблокированы.

## Настройка Google и Microsoft

Нужны собственные почтовые учётные записи и зарегистрированное OAuth-приложение.
Открывайте подключение в обычном браузере: провайдер может запретить встроенный.
Первичная конфигурация OAuth задаётся в защищённом локальном файле
`~/Library/Application Support/Quickly/secrets.env`, а не в форме на странице «Настройки».
Google: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Microsoft: `OFFICE365_CLIENT_ID`,
`OFFICE365_CLIENT_SECRET`, `OFFICE365_TENANT_ID`. После изменения конфигурации
нужно остановить и снова открыть Quickly через оболочку и обновить защищённую
копию конфигурации в Keychain (`macos/keychain.py save`). Существующие ключи
`QUICKLY_SECRET_KEY` и `QUICKLY_ENCRYPTION_KEY` при этом не менять.
Секреты не присылайте в чат. OAuth-токены в базе зашифрованы внешним ключом.

**Google:** создайте проект Google Cloud, включите Gmail API, настройте экран
согласия, добавьте свои адреса как тестовых пользователей и создайте OAuth-клиент
типа **Web application**. Redirect URI подключения ящиков:
`http://localhost:8765/oauth/google/callback`.
Сохраните Google Client ID / Client Secret в указанной локальной конфигурации,
перезапустите Quickly и подключите каждый ящик через «Почтовые аккаунты».
Штатный Quickly запрашивает `https://mail.google.com/` и `userinfo.email`.
Это широкое разрешение почты; для публикации приложения может потребоваться
проверка Google. В режиме External/Testing refresh-токены могут иметь ограниченный
срок; появившуюся ошибку решайте повторным OAuth-входом, а не заменой отправителя.
[Официальный порядок OAuth](https://developers.google.com/workspace/gmail/api/auth/web-server).

**Microsoft:** зарегистрируйте приложение в Microsoft Entra, выберите поддержку
нужных организационных/личных аккаунтов, добавьте Web redirect URI
`http://localhost:8765/oauth/office365/callback` и создайте client secret.
Штатные delegated-разрешения: `Mail.ReadWrite`, `Mail.Send`, `User.Read`, `offline_access`.
Укажите Client ID / Secret и Tenant ID в той же локальной конфигурации
(`common` подходит только если выбранный тип
приложения допускает соответствующие аккаунты). Политика организации может требовать
согласия администратора. [Справочник разрешений](https://learn.microsoft.com/en-us/graph/permissions-reference).

Для необязательного входа в сам Quickly через провайдера дополнительно предусмотрены
`/oauth/app/google/callback` и `/oauth/app/microsoft/callback` на том же localhost.
Локальный вход admin от них не зависит. Исходная подробная установка: `docs/INSTALL.md`.

## Проверка между своими ящиками

Откройте **Прогрев и диагностика → Автоматическая групповая диагностика**.
Выберите все собственные ящики либо отфильтруйте список, посмотрите распределение,
задайте интервал полного цикла, часы/дни по Москве и два предела: исходных проверок
на ящик в сутки и всех диагностических сообщений группы в сутки. Подтвердите
принадлежность, сохраните выключенную группу и включите расписание отдельной кнопкой.
Пошаговый пример для 500 ящиков — в [инструкции по меню](ПОШАГОВО.md#7-для-чего-прогрев-и-диагностика).

Один цикл создаёт по одной исходной проверке на доступного участника. Детерминированное
круговое распределение меняет смещение в следующем цикле, исключает отправку самому
себе и не создаёт матрицу всех пар. Очередь и её распределение сохраняются в PostgreSQL.
Повторная постановка при наличии ожидающих заданий не дублирует цикл. Пауза сохраняет
очередь; отмена ожидающих заданий сохраняет историю. Ошибки не переносятся на другой ящик.

Планировщик каждую минуту берёт до 20 отправок и до 20 проверок получения;
параллельность ограничена четырьмя обработчиками. Реальная длительность зависит
от сети и квот, поэтому время завершения цикла не гарантируется. Неполная конфигурация
SMTP/IMAP, паузы и известные ошибки исключают участника при распределении;
состояние проверяется повторно перед отправкой. Исходный и групповой счётчики
обновляются атомарно. Дополнительно действует общий дневной предел ящика и ramp-up.
Зарезервированные неудачные попытки тоже могут расходовать бюджет.

По желанию включите обозначенный диагностический ответ: он отправляется только после
подтверждения исходного получения. Ответ расходует бюджет группы и обычный лимит
отвечающего ящика; предел исходных проверок группы учитывает только первоначальные
пробы. Для 500 ящиков с одной пробой и одним ответом на ящик потребуется до 1000
сообщений группы за сутки, при достаточной обычной квоте каждого ящика.

`Quickly DIAGNOSTIC` ищется через IMAP или официальный API в доступных папках.
Заголовки SPF/DKIM/DMARC показываются только если получены от сервиса. Время в отчёте —
до обнаружения письма, включая интервал опроса. Принятие SMTP-сервером не доказывает
доставку и не определяет папку. Фильтры истории позволяют выбрать группу и ящик.
После прерывания взятое в обработку задание сохраняется с неопределённым результатом
и автоматически не повторяется. Перед ручными действиями проверьте исходящие.

Разовую отправку между выбранными двумя ящиками и прежнее парное расписание можно
создать в раскрывающемся блоке **Ручная проверка выбранной пары**. У парного расписания
ответ запрашивается вручную после подтверждения получения.

DNS-проверка показывает опубликованные SPF/DMARC и DKIM по вашему настоящему селектору.
Она не даёт оценки репутации. Необязательный Google Postmaster использует официальный
API с отдельным OAuth-токеном `postmaster.readonly` и вашим подтверждённым доменом.
Это токен Postmaster, а не пароль ящика; по истечении замените его в локальной форме.
Адаптер не запрашивает его, пока вы не настроите подключение. Статистика может быть
недоступна при малом объёме писем.
[Описание API](https://developers.google.com/workspace/gmail/postmaster/reference/rest/v1/domains.trafficStats/list).

## Контакты и кампании

В **Контактах** доступны CSV/XLSX, ручное добавление, поиск, сегмент/город/ОКВЭД,
произвольные поля и чёрный список. Скачайте образец файла. Разрешение хранится
в полях `consent_date` (ГГГГ-ММ-ДД) и `consent_basis`; исходный источник — в `source`.
Публичный адрес сам по себе не доказывает согласие на рекламу. Контакт без разрешения
можно сохранить как черновой, но отправка кампании ему заблокирована.

Повторный импорт удаляет дубликаты и обновляет поля, сохраняя отписки/блокировки.
Выберите контакты и добавьте в нужную кампанию. Нажатие на email открывает историю.
В **Кампаниях** создайте кампанию, выберите отправителей, дни/часы и часовой пояс,
добавьте этапы с темами, обычным текстом/HTML и задержками. Сохраняются штатные
предпросмотр, тестовая отправка, персонализация `{{name}}`, `{{company}}` и другие поля.
Включённая остановка после ответа прекращает дальнейшие этапы. Отказ и отписка тоже
останавливают цепочку. Общие входящие поддерживают фильтры интереса, автоответа,
новых ответов, отписок и отказов доставки; локальная классификация не требует AI API.
Неопределённый ответ остаётся без положительной оценки.

Нажмите **Проверить готовность кампании**. Потребуются отправители, письма,
разрешения контактов и публичные ссылки отписки. При отсутствии ящиков эту проверку
пройти нельзя. Создание кампании само по себе не снимает общую блокировку.

**Разрешить кампании…** требует ввода `РАЗРЕШАЮ ОТПРАВКУ`. Сейчас разрешение не дано.
**Остановить все отправки** блокирует новые кампании, тесты, диагностику, ответы и
почтовые уведомления. Уже принятые внешним сервером письма отозвать невозможно.
При снятии аварийной остановки кампании остаются заблокированными до нового разрешения.
**Отменить кампанию и очередь** сохраняет историю и запрещает повторный запуск этой
кампании; для нового запуска нужна её копия. Пауза в настройках кампании обратима.

Лимиты считаются по каждому ящику по московским суткам и включают попытки кампаний,
проверок, диагностики и ручных ответов. Отказ тоже расходует резерв: это консервативная
защита от превышения. Ramp-up может дополнительно уменьшить выбранный предел.
Операция сохраняется до обращения к сети. После сбоя с неизвестным результатом она
не повторяется автоматически: сначала проверьте исходящие вручную. Невозможно
гарантировать ровно одну доставку через SMTP при аварии сети; здесь выбран запрет
слепого повтора. Журнал показывает принятие сервером, отказ и неизвестный результат.

Ошибки авторизации приостанавливают ящик. Также действует остановка при 3 отказах
и доле отказов не менее 30% среди последних 20 операций за сутки, при 3 подтверждённых
возвратах за сутки и распознанной жалобе ARF. Доступность жалоб зависит от провайдера:
система не видит сообщения/отчёты, которые сервис ей не предоставляет. Другой ящик
автоматически для обхода такого отказа не используется. Исправьте причину и только
потом вручную снимайте паузу. Если сервер явно отказал в авторизации до принятия письма,
явное возобновление разрешает новую попытку кампании. Предыдущий отказ и расход квоты
сохраняются. Принятые, начатые и неопределённые операции автоматически не повторяются.

## Публичные HTTPS-ссылки

localhost доступен только на этом Mac. До реальной кампании настройте отдельный
публичный HTTPS-домен и укажите его в параметрах ссылок выбранных отправителей.
Подготовлен пример `macos/public-links/compose.yml` и `Caddyfile`: наружу разрешены
только `/u/*`, `/o/*`, `/c/*`; административные страницы возвращают 404.
Он **не запущен**. Нужны собственный домен, DNS, доступные 80/443 и постоянно работающий
Mac/сервер. Сначала проверьте отписку с внешнего устройства. Приложение проверяет
формат HTTPS-домена, но не может гарантировать его внешнюю доступность.
Встроенный Beacon также остаётся доступным вариантом. Уведомления OAuth через
публичные webhooks для localhost не настроены: входящие обновляются опросом.

## Резервные копии и восстановление

В Quickly.app выберите **Резервная копия**. Создаётся полный PostgreSQL dump со всеми
таблицами, включая диагностику, квоты и журнал. Файлы: `~/Library/Application Support/Quickly/backups/`.
**Восстановить копию** сначала создаёт резервную копию текущего состояния, восстанавливает
файл в отдельную базу, затем переключает только Quickly. Предыдущая база сохраняется
с именем `quickly_before_restore_…`. Если приложение не запускается, возвращается
предыдущая база. Во время переключения Quickly кратко недоступен.

Для расшифровки нужен тот же внешний ключ. Сохраняйте отдельно и безопасно
`~/Library/Application Support/Quickly/secrets.env` и `postgres-password`.
Одна копия БД без ключа не восстановит секреты ящиков. Ключи дополнительно сохранены
в macOS Keychain, запись `local.quickly.secrets`; `macos/keychain.py restore` возвращает
утраченный secrets.env без перезаписи существующего. Не публикуйте и не отправляйте
эти файлы. На другом Mac потребуется перенос ключей через защищённое хранилище.
Журнал оболочки: `~/Library/Application Support/Quickly/logs/launcher.log`.

Для специалиста: `macos/quickly status|logs|backup|verify-backup` и
`macos/restore.py /путь/копия.dump --replace-local-database`.
Штатный мастер Quickly .qbk также сохранён. Он восстанавливает копию в проверочную
базу, проверяет администратора и расшифровку секретов, сохраняет текущую копию и
переключает имена подготовленной и прежней баз в одной транзакции PostgreSQL.
Любой ненулевой код pg_restore — ошибка.
Перед заменой завершаются активные HTTP/фоновые операции; новые временно получают 503.
При ошибке SQL прежние данные остаются в рабочей базе.

Оба способа восстановления включают STOP, выключают кампании и приостанавливают
диагностические расписания до ручного возобновления. Не удаляйте резервную копию
и старую базу, пока не проверили результат.

Автозапуск использует копию служебных файлов в
`~/Library/Application Support/Quickly/service/`, чтобы macOS не блокировала доступ
LaunchAgent к Documents. После изменений macOS-скриптов повторно выполните
`macos/install-autostart.py` и `macos/install-launcher.py`.


## Изменения после повторного аудита 21 октября 2026

**Наблюдение.** На странице диагностики доступны сроки 24/48/72 часа (48 по
умолчанию) и интервалы от 1 до 60 минут (5 по умолчанию). Отсчёт идёт от
подтверждения принятия сервером; для старой истории без этой даты используется
сохранённая дата попытки/создания, без выдуманной даты принятия. Повторные
безрезультатные чтения замедляются до одного раза в час. Retry-After провайдера
хранится для всего получающего аккаунта. Ручная проверка не отправляет письмо
заново и не обходит временную блокировку провайдера.

**Соединения.** Верхнее поле страницы диагностики задаёт общий предел 1–16
соединений (по умолчанию 4). Чтение/проверки подключения занимают максимум
половину, минимум одно место. Это предел для одного процесса: установленный Mac
запускает один процесс сервера. Значение не ускоряет само расписание, которое
по-прежнему берёт до 20 отправок и 20 проверок за минутный такт. Группы обслуживаются
по очереди; ошибка исходящего SMTP одного ящика не считается доказательством,
что его исправный IMAP не может принять письмо другого участника.

**Журнал и CSV.** Показаны адреса, попытка/принятие/получение, папка, последняя и
следующая проверка, число попыток, срок наблюдения, причина и отдельный статус
транспорта. Фильтры группы/аккаунта действуют и для CSV. CSV выгружает всю
совпадающую историю, UI — последние 200 записей. Заголовки/тела и секреты не
экспортируются; значения, похожие на формулы таблиц, обезвреживаются.

**Восстановление.** В «Настройки → Настройка → Резервное копирование и восстановление» сначала выполните предпросмотр,
затем явное восстановление. Архив восстанавливается в отдельную базу; миграции,
шифрование, администратор и структура проверяются до переключения. Прежнее
состояние дополнительно сохраняется и проверяется отдельно. На время операции
новые действия блокируются, текущие завершаются. Предыдущая база и проверенная
копия автоматически не удаляются. После успешного восстановления STOP включён,
кампании запрещены, все диагностические расписания выключены. Их нужно проверять
и включать отдельно. При сбое переключения/инициализации используется прежняя
база; незавершённое восстановление проверяется при запуске по сохранённому журналу.
При полном отказе PostgreSQL/диска откат ждёт возвращения сервера: успешный откат
в таком состоянии программа не объявляет.

**API/MCP.** Пустой список scopes у старых ключей и `*` сохраняют полный доступ
в пределах роли владельца. `read` читает, `leads:read` читает контакты,
`leads:write` создаёт/редактирует/удаляет контакты, но не меняет участие в кампании
и не запускает восстановление или отправки. `write` разрешает общие изменения,
однако для выпуска/отзыва API-ключей нужны `*` либо обычный вход. Возобновление
участия контактов в кампании требует общего права `write`/`*` либо обычного входа.
Одинаковые правила применяются к Bearer, X-API-Key и инструментам MCP.
Административные действия дополнительно требуют роли администратора.

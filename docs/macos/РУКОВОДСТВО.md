# Quickly на Mac

## Открытие и остановка

В Finder откройте `~/Applications/Quickly.app`. Выберите «Открыть».
Docker должен завершить первоначальную настройку. Интерфейс: http://localhost:8765.
При первом входе создайте локального администратора через форму.
Кнопка «Остановить» в Quickly.app останавливает только контейнеры проекта quickly-mac.
Данные PostgreSQL остаются в томе quickly_mac_pgdata.

## Файлы и резервные копии

Конфигурация и секреты: `~/Library/Application Support/Quickly/secrets.env`.
Пароль PostgreSQL: `~/Library/Application Support/Quickly/postgres-password`.
Резервные копии: `~/Library/Application Support/Quickly/backups/`.
Журнал запуска: `~/Library/Application Support/Quickly/logs/launcher.log`.

Ключ шифрования хранится вне базы. Для переноса на другой компьютер сохраните
secrets.env и postgres-password отдельно и безопасно: одна копия БД без ключа
не позволит расшифровать пароли ящиков. Никому не отправляйте эти файлы и не добавляйте их в Git.

«Резервная копия» в Quickly.app создаёт PostgreSQL dump. В самом Quickly также есть
штатный мастер копирования/восстановления .qbk с паролем. Проверка обычного dump
через `macos/quickly verify-backup /полный/путь.dump` восстанавливает его в новую
временную БД этого же изолированного контейнера и затем удаляет только проверочную БД.

## Почтовые провайдеры

Gmail подключайте через Google OAuth. Microsoft/Outlook — через Microsoft OAuth.
Для этого нужны собственные приложения в Google Cloud и Microsoft Entra и разрешение пользователя.
Добавьте client ID/secret в secrets.env и перезапустите только Quickly.
Redirect URI для подключения ящиков:

- Google: `http://localhost:8765/oauth/google/callback`
- Microsoft: `http://localhost:8765/oauth/office365/callback`

Redirect URI для входа через провайдера (не обязателен при локальном логине):

- Google: `http://localhost:8765/oauth/app/google/callback`
- Microsoft: `http://localhost:8765/oauth/app/microsoft/callback`

Названия переменных: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, OFFICE365_CLIENT_ID,
OFFICE365_CLIENT_SECRET, OFFICE365_TENANT_ID. Не присылайте секреты в чат.

Яндекс и Mail.ru подключаются через SMTP/IMAP с паролями приложений и разрешённым
доступом к протоколам в настройках провайдера. Для корпоративной почты используйте
параметры, предоставленные администратором. TLS и сертификаты не отключайте.

Полные исходные инструкции OAuth находятся в docs/INSTALL.md и docs/OFFICE365_SETUP.md.

## Публичные ссылки

localhost доступен только на этом Mac. Получатели в интернете не смогут открыть
такие ссылки отписки или отслеживания. Перед реальной кампанией нужен отдельно
настроенный публичный HTTPS-адрес для этих функций (например, Quickly Beacon).
Это не требует публикации административного интерфейса. Webhooks провайдеров
также требуют соответствующего HTTPS-адреса; при локальном запуске используйте опрос.

Публично найденный адрес не подтверждает согласие на рекламу. Загружайте только
контакты, которым разрешено отправлять ваши письма.

## Состояние установки

Это руководство описывает подготовленную конфигурацию. Фактический статус запуска
и результаты проверок будут перечислены в отчёте TEST-RESULTS.md после тестирования.

Копию ключей можно сохранить в macOS «Связка ключей»: `python3 macos/keychain.py save`.
Восстановление при потере secrets.env: `python3 macos/keychain.py restore` (не перезаписывает существующий файл).
Элемент называется local.quickly.secrets. Сам пароль базы хранится также в postgres-password;
сохраняйте этот файл отдельно при переносе установки.

# Аудит и исправления Quickly — 21 октября 2026

Проверена локальная версия на Mac. Исходное состояние: commit `450b635`.
Ошибки воспроизведены в отдельных базах, исправления добавлены в эту ветку.
Рабочая база не использовалась для повреждения копий и нагрузочных экспериментов.

## Найденные ошибки и результат

|---|---|---|
| P1 | Веб-восстановление принимало ненулевой код pg_restore за предупреждение и могло повредить текущие таблицы. | Полная проверка копии и внешнего ключа в отдельной базе, копия прежнего состояния, замена одной транзакцией. Любой ненулевой код — ошибка. Текущие операции завершаются перед заменой. |
| P1 | После отказа авторизации зарезервированный ключ задания навсегда блокировал кампанию даже после исправления пароля. | Явное снятие паузы разрешает новую попытку только для подтверждённого отказа авторизации до принятия письма. Журнал и потраченная квота сохраняются. Принятые и неопределённые операции не освобождаются. |
| P2 | Локальное время Москвы повторно интерпретировалось как UTC; окно отправки смещалось на три часа. | В базе и очереди используется UTC; разрешённые часы проверяются в часовом поясе кампании. Группы используют Москву. |
| P2 | Диагностические письма и ответы обходили интервал одного отправителя. | Общая атомарная отметка времени для автоматических кампаний, проверок и автоответов. Ожидание не расходует квоту и сохраняет задание в очереди. |
| P2 | LaunchAgent получал Operation not permitted при обращении к Documents и завершался с кодом 126. | Служебные скрипты и Compose скопированы в Application Support. Новый LaunchAgent реально выполнен, код завершения 0. |

| P2 | Карточка отправителя не учитывала диагностику и местные сутки; попытки смешивались с успешным принятием. | Общие московские сутки и журнал для всех провайдеров. Отдельно показаны расход попыток и подтверждённое принятие сервером. |

| P2 | API-ключ с правом read мог менять настройки отправки. | Права проверяются на сервере для ключей в заголовке и Bearer. Поддерживаются read, write, leads:read, leads:write и полный доступ; форма создания предлагает явный выбор. |

Добавлена кнопка **Изменить настройки группы**. Меняются название, период, лимиты,
дни/часы и автоответ. Сохранение приостанавливает группу, сохраняя участников,
очередь, историю и уже потраченные квоты. Уменьшение лимита не обнуляет расход.

После восстановления через веб-мастер или оболочку Mac отправка остановлена,
кампании запрещены, диагностические расписания приостановлены. В оболочке Mac
внешний ключ и миграции проверяются до переключения рабочей базы.

Ввод и результат HTML-редактора дополнительно проходят DOMPurify. Это прикладная
защита, а не обновление неисправленной зависимости Quill.

## Подтверждение

- PostgreSQL: **578 passed**, полный набор, 4 минуты 23 секунды.
- SQLite: **569 passed, 9 skipped**. Пропуски относятся к PostgreSQL-сценариям.
- Две Node-проверки русификации: **2 passed**. Frontend и Docker собираются.
- Отдельная PostgreSQL-проверка: 1000 участников, 1000 уникальных заданий;
  52 конкурентных обработки при пределе 7 дали ровно 7 имитированных отправок.
  Оба групповых счётчика и журнал равны 7.
- 30 конкурентных попыток одного ящика при заданном интервале дали ровно одну
  имитированную отправку. Импорт 10 000 контактов занял около 0,42 секунды.
- Повреждённая копия и неверный ключ отклонены до замены целевой базы.
  Ошибка SQL во время замены откатила транзакцию и сохранила прежнего пользователя.
  Успешное восстановление сохранило 1000 ящиков, 10 000 контактов и предыдущую копию.
- Браузером проверены вход и изменение сохранённой группы на 1000 аккаунтов:
  предел изменён с 1000 на 2000, исходных проверок на ящик — с 1 на 2,
  очередь из 1000 заданий сохранилась, группа приостановлена.
- В рабочей установке проверены вход администратора и отказ 401 без авторизации.
  Итоговые данные: 1 администратор, 0 ящиков, 0 контактов, 0 кампаний, 0 отправок.

Регрессии: `tests/test_audit_fixes.py`. Воспроизводимые отдельные проверки:
`scripts/validate_audit_postgres.py` и `scripts/validate_restore_safety.py`;
последняя намеренно допускает только тестовую базу с заданным именем и требует
подготовленных синтетических dump-файлов. Не запускайте её на рабочих данных.


Дополнительно в браузере сохранён HTML-этап кампании: жирный текст, {{name}} и
ссылка {{unsubscribe_link}} сохранились в базе. Проверено отсутствие зацикливания
при различиях HTML-сериализации Quill и DOMPurify (например, target у ссылки).

## Границы проверки

Реальных ящиков у пользователя пока нет. Живые OAuth-согласия, пароли приложений,
доставка и папки Google/Microsoft/Яндекс/Mail.ru требуют проверки после подключения.
Тестовые SMTP/IMAP и имитации API не подтверждают работу чужих сервисов на будущих
аккаунтах. Внешние почтовые сообщения во время аудита не отправлялись.

Проверен запуск LaunchAgent в текущей сессии macOS; физический перезапуск Mac
не выполнялся. Проверка 1000 ящиков подтверждает очередь, квоты, импорт и интерфейс,
но не является измерением одновременной сетевой работы 1000 реальных аккаунтов.

Python lockfile: известных уязвимостей не найдено. npm оставляет две записи low
для Quill 2.0.3 и его обёртки, без moderate/high/critical. Исправленная версия
для [GHSA-v3m3-f69x-jf25](https://github.com/advisories/GHSA-v3m3-f69x-jf25)
не опубликована на момент проверки. Остались предупреждения об устаревающих API
в тестах и размере JS-пакета; они не приводят к падению выполненных проверок.

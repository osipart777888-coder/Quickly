# Quickly: понятная инструкция по меню и первым действиям

Эта инструкция относится к установленной на вашем Mac версии Quickly.
Открыть программу: **[http://localhost:8765](http://localhost:8765)**.

**Самое нужное:** адреса клиентов загружаются в **Контакты → Импорт контактов CSV / XLSX**.
Ваши собственные ящики подключаются в **Почтовые аккаунты**.
Письма и последовательность отправки создаются в **Кампаниях**.

## 1. Как запустить и что можно делать уже сейчас

1. Откройте Finder → свою папку пользователя → **Applications → Quickly.app**.
2. Выберите **Открыть Quickly**. Откроется браузер с программой.
3. Войдите под логином **admin**. Пароль можно посмотреть в **Quickly.app → Данные входа**.
4. Если слева видны только значки, нажмите **Развернуть меню** внизу боковой панели.

Quickly.app — небольшое окно запуска. Контакты, кампании и остальные настройки находятся
в открывшемся браузере. Docker Desktop должен работать. Когда Mac выключен или спит,
локальная программа не выполняет отправки. Данные остаются сохранёнными.

Пока у вас нет почтовых ящиков, можно загружать контакты, разделять их по сегментам,
создавать кампании и готовить тексты. Отправка станет возможной после подключения
ящиков и завершения настройки. Надпись **Отправка кампаний заблокирована** сейчас ожидаема.

## 2. Какое меню для чего

| Раздел слева | Что здесь делать |
|---|---|
| **Главная** | Смотреть общие показатели, ошибки и состояние своих ящиков. |
| **Почтовые аккаунты** | Подключать свои адреса отправителей, задавать лимиты и проверять соединение. |
| **Контакты** | Загружать адреса клиентов, искать их, выбирать сегменты и добавлять в кампании. |
| **Кампании** | Создавать рассылки, писать письма, добавлять этапы и выбирать время отправки. |
| **Очередь и расписание** | Смотреть, каким получателям, из каких ящиков и когда запланированы письма. |
| **Общие входящие** | Читать ответы по подключённым ящикам и отвечать на них. |
| **Прогрев и диагностика** | Проверять связь между собственными ящиками, DNS и результаты тестов. |
| **Журнал отправки** | Разбирать последние попытки: принято сервером, отказано или результат неизвестен. |
| **Аналитика** | Изучать статистику кампаний, ответов, открытий и переходов. |
| **Уведомления** | Читать уведомления самой программы. |
| **Настройки** | Настраивать синхронизацию, копирование, внешний вид и дополнительные функции. |
| **Состояние системы** | Смотреть техническое состояние приложения и почтовых подключений. |

**Последовательности писем** находятся внутри выбранной кампании, отдельного пункта
в левом меню для них нет. Настройки конкретной кампании тоже находятся внутри неё.

## 3. Как загрузить контакты клиентов

Откройте **[Контакты](http://localhost:8765/leads)**.

### Загрузка файла

1. Нажмите **Скачать образец CSV контактов**.
2. Откройте образец в Excel, Numbers или другой табличной программе.
3. Замените пример своими данными. В первой строке оставьте названия колонок.
4. Сохраните в **CSV** или **XLSX**. Для CSV предпочтительна кодировка UTF-8.
5. Вернитесь в **Контакты** и нажмите **Импорт контактов CSV / XLSX**.
6. Выберите файл. Программа сразу обработает его.
7. Посмотрите сообщение о количестве добавленных, обновлённых, повторных и некорректных строк.
   Если указаны ошибки, исправьте соответствующие строки в исходном файле и загрузите снова.

Для XLSX проще использовать один лист: импорт читает активный лист книги.
Не делайте объединённых ячеек и отдельных строк-заголовков над названиями колонок.
Одна строка должна соответствовать одному человеку или адресу.
Файл — до 20 МБ, не более 100 000 строк за один импорт.

| Название колонки в образце | Что туда записать |
|---|---|
| `email` | Адрес получателя. Это обязательная колонка. |
| `name` | Имя человека. |
| `company` | Компания. |
| `city` | Город. |
| `okved` | ОКВЭД; удобно хранить как текст, чтобы таблица не меняла формат. |
| `title` | Должность. |
| `source` | Откуда появился контакт: например, входящий запрос клиента. |
| `consent_date` | Реальная дата разрешения на отправку в формате ГГГГ-ММ-ДД. |
| `consent_basis` | На каком основании разрешено писать этому получателю. |
| `segment` | Ваша группа: например, «Действующие клиенты» или «Запросы на расчёт». |

Дополнительные колонки сохраняются как дополнительные поля контакта.
Можно использовать русские заголовки, но для первого импорта надёжнее оставить
названия из скачанного образца.

Без даты и основания разрешения контакт сохранится, однако отправка кампании ему
будет заблокирована. Заполняйте эти поля по фактическим данным: найденный в интернете
email сам по себе не подтверждает разрешение на рекламную рассылку.

Повторы в одном файле пропускаются. Если адрес уже есть в базе, данные контакта
могут обновиться; новая копия адреса не создаётся. Повторный импорт не снимает отписку
или блокировку. Перед большим обновлением сделайте резервную копию.

**На этой странице есть и другая кнопка — «Загрузить CSV с исправленными адресами».**
Она предназначена для восстановления ранее добавленных контактов после исправления
адресов. Для первоначального списка используйте именно **Импорт контактов CSV / XLSX**.

### Добавление одного человека

Нажмите **Добавить контакт вручную**, заполните поля и нажмите **Сохранить контакт**.
Кнопка **Добавить дополнительное поле** позволяет сохранить свои сведения о клиенте.

### Поиск, сегменты и чёрный список

В поле поиска ищите адрес или имя. Для сегмента заполните **Сегмент**, **Город** и/или
**ОКВЭД**, затем нажмите **Применить фильтры сегмента**. Ненужные фильтры очистите
и примените ещё раз. Пример: в `segment` при импорте указано «Запросы на расчёт» —
это же значение введите в фильтр **Сегмент**.

Нажатие на email открывает карточку и историю контакта. Кнопка **Чёрный список**
позволяет исключить адрес из дальнейшей отправки и указать причину.

### Как передать контакты в кампанию

1. Сначала создайте кампанию, как описано в разделе 5.
2. В **Контактах** найдите нужных получателей или примените фильтры.
3. Отметьте нужные строки флажками слева.
4. Над списком появятся выбор кампании и кнопка **Добавить выбранные контакты в кампанию**.
5. Выберите свою кампанию и нажмите эту кнопку.

Сам импорт в базу не начинает отправку и не добавляет всех людей во все кампании.

## 4. Как подключить собственные почтовые ящики

Откройте **[Почтовые аккаунты](http://localhost:8765/inboxes)**.
Здесь должны быть ваши адреса, с которых отправляются письма, а не адреса клиентов.

### Яндекс, Mail.ru или корпоративная почта

1. Нажмите **Добавить Яндекс / Mail.ru / корпоративный ящик**.
2. Выберите провайдера. Для Яндекса и Mail.ru серверы подставятся автоматически.
3. Укажите свой полный email, имя отправителя и дневной лимит.
4. Введите **пароль приложения**, созданный в настройках почтового сервиса.
5. Нажмите **Сохранить ящик**.
6. В таблице состояния нажмите **Проверить подключение**.

SMTP — отправка писем, IMAP — чтение входящих. Для корпоративного сервера параметры
нужно получить у администратора почты. Подробные значения серверов и порядок
подключения провайдеров есть в [техническом руководстве](РУКОВОДСТВО.md).

**Проверить подключение** не отправляет письмо: проверяет доступ к сервису.
Полноценный обмен письмами проверяется в разделе диагностики.

### Gmail и Microsoft / Outlook

Нажмите обычную кнопку **Добавить ящик**, выберите Google или Microsoft и пройдите
вход через провайдера. Первый запуск требует отдельной настройки вашего OAuth-приложения.
Если программа сообщает, что OAuth не настроен, эта настройка ещё не выполнена.

**В текущей версии нет формы для ввода Google/Microsoft Client ID и Client Secret
на странице «Настройки».** Они задаются в локальной конфигурации и применяются после
перезапуска Quickly. Пока ящиков нет, этот шаг можно отложить. Порядок настройки
и точные параметры перечислены в [разделе про Google и Microsoft](РУКОВОДСТВО.md#настройка-google-и-microsoft).
Пароль Gmail/Outlook в форму обычного SMTP вводить не нужно.

### Где изменить лимит, интервалы и постепенное увеличение

Откройте нужный ящик в списке и нажмите **Изменить**. Здесь находятся:

| Параметр | Значение |
|---|---|
| **Максимум писем в сутки** | Верхний предел для этого конкретного отправителя. |
| **Интервал между письмами, минут** | Минимальная пауза между письмами одного ящика. |
| **Случайная задержка, минут** | Дополнительная случайная пауза от нуля до указанного значения. |
| **Постепенное увеличение лимита** | Ramp-up: меньший начальный предел с постепенным ростом до вашего максимума. |
| **SMTP / IMAP** | Серверы, порты, логины и пароли приложения для обычной почты. |
| Параметры ссылок и отслеживания | Домен для отписки и, при включении, открытий/переходов. |

После изменения нажмите **Сохранить**. Для Google/Microsoft также проверяйте лимит
в обычной форме: у неё может стоять 50 по умолчанию. Упрощённая SMTP-форма начинает с 5.
Устанавливайте предел с учётом правил вашего провайдера.

Интервал одного ящика действует на автоматические кампании, групповые проверки и
диагностические автоответы вместе. Пока пауза не истекла, задание ждёт в очереди
и не расходует квоту. Ручная проверка или ответ запускаются по вашему действию;
они расходуют дневной лимит и отодвигают следующую автоматическую отправку.
**Попыток сегодня** — расход дневной квоты, включая отказы. **Принято сервером сегодня** —
только подтверждённое принятие сервером; это ещё не доказательство доставки.

Дневной лимит общий для кампаний, тестовых писем, диагностики и ручных ответов.
Например, при пределе 5 три письма кампании, один тест и одно диагностическое письмо
уже используют дневной бюджет. Неудачная попытка тоже может расходовать резерв.
Сутки для квоты считаются по Москве. При включённом ramp-up фактический предел
может быть меньше установленного максимума.

**Импорт аккаунтов из CSV** нужен только для массовой загрузки конфигураций собственных
SMTP/IMAP-ящиков. Образец скачивается рядом. Файл с клиентскими адресами сюда не загружайте.

## 5. Как подготовить кампанию и последовательность писем

### Создайте кампанию

1. Откройте **[Кампании](http://localhost:8765/campaigns)** → **Создать кампанию**.
2. Введите понятное название, например «Предложения по запросам клиентов».
3. Выберите свои ящики отправителей. Если ящиков ещё нет, можно создать заготовку без них.
4. Выберите дни и часы отправки, укажите часовой пояс.
5. Оставьте включённой остановку последовательности после ответа.
6. Нажмите **Создать кампанию**.

Внутри кампании есть вкладки:

| Вкладка | Что в ней делать |
|---|---|
| **Аналитика** | Смотреть результаты только этой кампании. |
| **Последовательности** | Писать первое письмо и следующие этапы. |
| **Контакты** | Проверять получателей этой кампании, их статусы и персональные данные. |
| **Очередь** | Смотреть ожидающие письма и назначенных отправителей. |
| **Настройки** | Менять отправителей, расписание, часовой пояс, паузу и дополнительные параметры. |

### Добавьте письма

1. Откройте **Последовательности** → **Добавить этап**.
2. Напишите тему и текст.
3. Для обычного письма оставьте **Отправлять в HTML** выключенным.
   Для оформления с жирным текстом, списками и ссылками включите HTML.
4. Для первого этапа оставьте 0 дней после предыдущего.
5. Нажмите **Добавить этап** или **Сохранить изменения**, если редактируете существующий.
6. При необходимости добавьте следующие этапы и задержки между ними.

Задержка следующего этапа задаётся **после предыдущего этапа**, а не обязательно
от начала всей кампании. Отправка дополнительно зависит от разрешённых дней/часов,
лимита ящика и очереди. Например, схема 0, 3, 4 дня задаёт первое письмо, затем паузу
3 дня и ещё 4 дня после второго этапа; фактическое время может сдвинуться по расписанию.

Для обычной общей последовательности оставьте тип **Общий текст для всех контактов**.
Режим **Персональное письмо для каждого контакта** требует отдельно подготовленных
текстов по каждому человеку; для первого знакомства он не нужен.

Переменные подставляют данные получателя. Пример текста:

> Здравствуйте, {{name}}! Подготовили информацию для {{company}} по вашему запросу.

`{{name}}` берётся из имени, `{{company}}` — из поля компании.
Проверьте, что эти поля заполнены. `{{unsubscribe_link}}` — ссылка отписки.
Откройте **Предпросмотр** и проверьте подстановки. Тестовую отправку направляйте
на свой адрес; она расходует лимит выбранного ящика.

### Добавьте получателей и проверьте готовность

Вернитесь в **Контакты** в левом меню, выберите людей и добавьте их в созданную
кампанию. Затем откройте кампанию и нажмите **Проверить готовность кампании**.

Проверка покажет, чего не хватает: отправителей, этапов, получателей, разрешений
на отправку или публичного HTTPS-домена отписки. Адрес localhost работает только
на этом Mac и не подходит для ссылки, которую должен открыть получатель в интернете.
Подготовленная конфигурация публичных ссылок описана в техническом руководстве;
сам домен пока не развёрнут.

**Создание кампании и её сохранение не снимают общую блокировку отправки.**
Когда всё проверено и вы действительно готовы отправлять разрешённые письма,
используйте верхнюю кнопку **Разрешить кампании…**. Она требует точную фразу
`РАЗРЕШАЮ ОТПРАВКУ`. Разрешение общее: после его выдачи могут работать все готовые
кампании без паузы, поэтому сначала проверьте их список.

## 6. Пауза, отмена и аварийная остановка

| Действие | Результат |
|---|---|
| Кампания → **Настройки → Приостановить кампанию** → сохранить | Временная пауза одной кампании. Возобновление — снять этот флажок и сохранить. |
| **Отменить кампанию и очередь** | Отменяет дальнейшую отправку этой кампании, сохраняет историю. Для нового запуска понадобится её копия. |
| Верхняя кнопка **Заблокировать кампании**, если они разрешены | Закрывает общий допуск кампаний. Ручные проверки остаются отдельными действиями. |
| Верхняя красная кнопка **Остановить все отправки** | Блокирует новые кампании, тесты, диагностику, ручные ответы и почтовые уведомления. |
| **Quickly.app → Остановить Quickly** | Останавливает саму программу и её базу; данные сохраняются. |

Снятие аварийной остановки не даёт заново разрешение кампаниям.
Уже принятое внешним почтовым сервером письмо отозвать этой кнопкой нельзя.
Для остановки не нужно удалять кампанию или её контакты.

## 7. Для чего «Прогрев и диагностика»

Здесь два разных механизма: постепенное увеличение лимита настраивается у ящика,
а диагностические письма проверяют связь между вашими собственными ящиками.

Если у вас 100 или 500 ящиков, выбирать каждую пару вручную не нужно. Сначала
подключите ящики в **Аккаунтах**; для SMTP-ящиков нужны и SMTP, и IMAP.

1. Откройте **[Прогрев и диагностика](http://localhost:8765/diagnostics)**.
2. В блоке **Автоматическая групповая диагностика** нажмите **Выбрать все аккаунты**.
   Можно выбрать часть списка: найдите адрес или отфильтруйте провайдера и нажмите
   **Выбрать найденные аккаунты**. Флажки позволяют поправить состав вручную.
3. Нажмите **Посмотреть распределение**. Предпросмотр показывает доступные ящики,
   пары и причины исключения остальных. Писем он не отправляет.
4. Задайте название, интервал полного цикла, дни и часы по Москве. Начальное
   значение интервала — 1440 минут, то есть раз в сутки в разрешённое время.
5. Оставьте для начала **Исходных проверок на ящик в сутки: 1**. Общий предел группы
   включает исходные проверки и ответы. При 500 доступных ящиках один цикл —
   500 исходных писем. С включёнными ответами потребуется до 1000 писем группы,
   а дневной предел каждого ящика должен позволять и проверку, и ответ.
6. Если нужен обмен в обе стороны, включите **Автоматически отправлять обозначенный
   диагностический ответ после подтверждённого получения**. По умолчанию это выключено.
7. Подтвердите принадлежность ящиков и нажмите **Сохранить группу выключенной**.
8. Ниже, в **Расписаниях диагностики**, нажмите **Включить расписание** у этой группы.

В каждом цикле каждый доступный ящик получает одного адресата из группы. Например,
А → Б, Б → В, В → А. В следующем цикле адресаты меняются. Проверки идут через очередь:
система не отправляет 500 писем одновременно и не создаёт переписку «каждый с каждым».
За проход планировщика берётся до 20 проверок, одновременно обрабатывается до 4.
Фактическое время зависит от серверов, разрешённых часов и квот.

Письма и ответы явно помечены DIAGNOSTIC. Ответ появляется только после обнаружения
исходного письма в принимающем ящике. Все сообщения расходуют обычный дневной лимит
ящика; постепенное увеличение лимита, паузы и общая аварийная остановка действуют и здесь.
Лимиты считаются консервативно по зарезервированным попыткам, включая неудачные.
Приостановленные, неполностью настроенные ящики и ящики с известной ошибкой подключения
исключаются. Перед отправкой состояние проверяется повторно. Неудачная проверка
не переносится на другой ящик.

Кнопки сохранённой группы:

- **Изменить настройки группы** — меняет название, интервал, исходные проверки на ящик,
  общий дневной предел, дни/часы и автоответ. Нажмите **Сохранить настройки и приостановить группу**,
  проверьте значения и снова **Включить расписание**. Участники, очередь, история
  и уже использованные квоты сохраняются. Уменьшение предела не обнуляет расход.
- **Остановить расписание** — приостанавливает новые отправки, сохраняя очередь.
- **Включить расписание** — продолжает оставшиеся проверки в разрешённое время.
- **Поставить следующий цикл в очередь** — заранее сохраняет распределение. У выключенной
  группы письма остаются в очереди. Пока есть ожидающие проверки, второй цикл не добавляется.
- **Отменить ожидающие проверки** — отменяет ещё не взятые в обработку задания,
  сохраняя историю. Уже начатую отправку отменить этой кнопкой нельзя.

В **Истории диагностики** выберите группу или конкретный аккаунт. Показаны последние
200 проверок по фильтрам; полный журнал остаётся в базе. При необходимости откройте
**Подробности** или вручную нажмите **Проверить получение**. Неопределённые результаты
после прерывания не повторяются автоматически: сначала проверьте исходящие.

Для одного разового теста раскройте **Ручная проверка выбранной пары**, выберите отправителя
и получателя, подтвердите принадлежность и нажмите **Запустить диагностику**. После
**Проверить получение** можно отдельно отправить диагностический ответ. Расписание
из этого блока сохраняет выбранную пару; групповой режим находится в верхнем блоке.
Если письмо ещё не найдено, проверьте позже и посмотрите доступность принимающего ящика.

Внизу страницы:

- **Аутентификация домена: SPF / DKIM / DMARC** — проверка DNS-записей своего домена.
  Для DKIM нужен настоящий селектор от провайдера.
- **Google Postmaster** — необязательная официальная статистика подтверждённого домена.
  Требует отдельного OAuth-доступа; для начала работы этот блок можно не заполнять.

Показанное время — до обнаружения письма, включая интервал опроса.
Точные папки и заголовки отображаются только при наличии доступа к ним.

## 8. Где читать ответы и смотреть результаты

**Общие входящие:** выберите переписку, чтобы прочитать текст и историю.
Фильтр статусов позволяет выбрать **Новые ответы**, **Заинтересован**, **Не заинтересован**,
**Автоматический ответ**, **Отписки** и **Отказ доставки**. Нажатие на переключатель
**Контакты / Все** меняет состав показываемых переписок.

Почта обновляется опросом, поэтому ответ не обязан появиться мгновенно.
Классификация простых ответов работает локально. Неоднозначный ответ может остаться
без оценки интереса — проверьте его вручную. Просьба не писать и отписка исключают
дальнейшую отправку. При включённой остановке по ответу цепочка прекращается после ответа.

**Главная** — общий обзор. **Аналитика** — более подробные показатели.
В **Кампания → Аналитика** показаны результаты конкретной кампании.
Открытия и переходы требуют соответствующих настроек отслеживания; они зависят
от поведения почтового клиента и не доказывают внимательное прочтение человеком.

**Журнал отправки** помогает понять результат операции:

| Статус | Что он означает |
|---|---|
| **Принято сервером** | SMTP-сервер или API подтвердил принятие. Конечная доставка ещё не доказана. |
| **Отказ сервера** | Отправка отклонена; посмотрите причину. |
| **Зарезервировано** | Намерение отправки сохранено до сетевого обращения. Автоматический повтор не выполняется. |
| **Результат неизвестен** | Подтверждение не получено, например после обрыва связи. Сначала проверьте исходящие вручную. |
| **Отменено** | Операция остановлена до обращения к почтовому серверу. |

## 9. Где находятся общие настройки

Откройте **[Настройки](http://localhost:8765/settings#general)**.

| Вкладка | Что внутри | Что нужно для начала |
|---|---|---|
| **Общие** | Распределение очереди по приоритетам/равномерно, внешний вид, учётная запись, известные IP, информация о версии. | Можно оставить текущие значения. RU/EN переключается верхней кнопкой. |
| **Настройка** | **Синхронизация Gmail**, **Резервное копирование и восстановление**. | Синхронизацию сначала оставить текущей; освоить резервную копию. |
| **Возможности** | Функции ИИ и прочие дополнительные функции, включая необязательную проверку адресов. | Платный AI API не требуется; можно ничего не подключать. |
| **Интеграция** | Ключи API, вебхуки и MCP для других программ. | Не нужны для обычной работы через браузер. |

Настройки определённого отправителя находятся в **Почтовые аккаунты → нужный ящик → Изменить**.
Настройки конкретной рассылки — в **Кампании → нужная кампания → Настройки**.
Настройки тестового обмена — в **Прогрев и диагностика**.
Почтовый пароль изменяется у почтового провайдера; в Quickly затем сохраняется новый
пароль приложения или заново выполняется OAuth-вход.

Ключи для других программ создаются в **Настройки → Интеграция → Ключи API**.
Выбирайте нужные права: полный доступ, только чтение, чтение контактов или чтение/изменение
контактов. Ключ для чтения не может включать отправки или менять настройки.

## 10. Как сохранить данные и восстановить копию

Самый простой способ — **Quickly.app → Резервная копия**.
Копии находятся в папке пользователя:
`Library/Application Support/Quickly/backups/`.

Создавайте копию перед большим импортом, массовыми изменениями и обновлением программы.
Для восстановления выберите **Quickly.app → Восстановить копию**, укажите файл `.dump`
и подтвердите действие. Приложение создаст копию текущего состояния и сохранит
предыдущую базу отдельно. Во время переключения Quickly ненадолго недоступен.

Встроенный мастер в **Настройки → Настройка → Резервное копирование и восстановление**
работает со своим форматом `.qbk`. Файл `.dump` из оболочки и `.qbk` из этого мастера
нужно восстанавливать соответствующим способом.
Оба способа сначала проверяют копию и внешний ключ в отдельной базе. Ошибка копии
не должна заменять рабочие данные. После успешного восстановления включена аварийная
остановка, кампании запрещены, расписания диагностики приостановлены. Проверьте
настройки, снимите аварийную остановку и включайте нужные расписания вручную.

Для переноса на другой компьютер требуется не только копия базы, но и внешний ключ
шифрования. Порядок безопасного сохранения ключей описан в [техническом руководстве](РУКОВОДСТВО.md#резервные-копии-и-восстановление).
Пароли и ключи на GitHub не загружаются.

## 11. Если что-то не получается

| Ситуация | Куда смотреть и что сделать |
|---|---|
| Программа не открывается | Откройте Docker Desktop, затем Quickly.app → Открыть Quickly. |
| Список контактов пустой после загрузки | Проверьте, что использовали импорт контактов, а не аккаунтов; посмотрите результат импорта, очистите фильтры. |
| Контакты есть, писем нет | Проверьте состав получателей кампании, её готовность, паузу, общее разрешение, расписание и лимит ящика. |
| Ошибка «не указано разрешение» | В карточке/исходном файле должны быть фактические `consent_date` и `consent_basis`; исправленный файл можно импортировать повторно. |
| Не подключается Яндекс или Mail.ru | Проверьте пароль приложения, разрешение IMAP/SMTP у провайдера и кнопку проверки соединения. |
| OAuth не настроен | Нужна первая настройка Google/Microsoft в локальной конфигурации; пароль SMTP это не исправит. |
| Ящик приостановился после ошибок | Посмотрите причину в Почтовых аккаунтах и Журнале отправки, исправьте доступ или причину отказов, затем вручную снимите паузу. |
| Дневной максимум 5, а отправилось меньше | Лимит могли занять тесты/диагностика/неудачные попытки; ramp-up и расписание тоже могут уменьшить фактическую отправку. |
| Нет диагностического получения | Проверьте IMAP/API получателя, повторите поиск позже и просмотрите доступные папки. |
| Результат отправки неизвестен | Проверьте папку исходящих у провайдера; не создавайте повтор вслепую. |
| Нужно немедленно остановить отправку | Красная кнопка **Остановить все отправки** вверху. |

## 12. Порядок первого рабочего запуска

1. Создать собственные почтовые ящики.
2. Подключить их в **Почтовых аккаунтах** и проверить соединение.
3. Проверить обмен между двумя своими ящиками в **Прогреве и диагностике**.
4. Загрузить разрешённые контакты в **Контакты**, проверить данные и сегменты.
5. Создать кампанию и письма в **Последовательностях**.
6. Добавить выбранных контактов в эту кампанию.
7. Настроить отправителей, лимиты, расписание и публичные ссылки отписки.
8. Проверить предпросмотр, тест на свой адрес и **Готовность кампании**.
9. Проверить, какие кампании готовы и не стоят на паузе; только затем дать общее разрешение отправки.
10. Смотреть очередь, журнал и ответы; делать резервные копии.

[результаты тестов и ограничения](TEST-RESULTS.md), [состояние версии](STATUS.md).
